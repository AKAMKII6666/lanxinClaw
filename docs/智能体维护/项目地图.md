# 项目地图

## 仓库职责

本仓库负责 Lanxing Claw protocol、desktop companion shell 与 OpenClaw integration boundary。

本仓库不负责澜星电话 call chain、张老板人格 prompt，也不负责 OpenClaw core execution internals。

## 当前事实

- 根目录已启用 npm workspaces（`apps/*`、`packages/*`）与共享 `tsconfig.base.json`。
- `packages/protocol`：types、validators、states、examples contract tests 已落地，并接入 `npm run quality`；含张老板 companion FC catalog（`COMPANION_FC_NAMES` / `COMPANION_FC_CATALOG`）。目录 type 在 protocol 包、schema、`examples/`、mock 与 companion 五处对齐；含 `permission.request` / `permission.decision` / `chat.context_attach` / `chat.read_receipt`。
- `apps/mock-companion`：pairing / session 门闩 / job 事件流 / 控制面板 UI 契约已落地；`job.create` 出站 `job.needs_permission` + `permission.request`，经 `POST /ui/permission-decide` 模拟桌面授权后再启动 mock worker；空 `allowedPermissions` 拒绝。
- `apps/companion`：discovery、pairing、identity、Electron 壳、bridge、总览/任务/权限/诊断/张老板页、permission gate 已按 v1.2–v1.3 推进。协议入站守卫（方向 + session 门闩）、`job.create` 幂等/affair 门闩/ack、`createBroadcast` apply 失败不 send；`job.needs_permission` 等出站须 companion→phone builder。deny/require_more_context → `permission.decision` + `job.failed`；`device.revokePairing` 真撤销 identity + `pairing.revoked`。Companion 重启恢复 in-flight poll（不重复 createRun）。WS 业务 envelope 只发给已认证 socket；`GET /snapshot` 仅回环。
- **日常入口**：`npm run start:companion`（打包后开窗，适合日常常驻）；`npm run dev:companion`（Vite + Electron 热更新）。托盘可勾选开机启动（`app.setLoginItemSettings`）、局域网监听（下次启动生效）、打开日志目录。Windows 安装包由 `npm run dist:win` 产出 NSIS x64 安装器，随包带 OpenClaw、Node 与 Qwen provider seed。
- **首次配置门（onboarding）**：默认千问（阿里云百炼）；地域与模型下拉预设见 `apps/companion/src/onboarding/presets/qwen.ts`，用户仅需粘贴 DashScope API Key；UI 在 `apps/companion/src/ui/pages/onboarding/config-gate.tsx`。
- **协议收口（2026-08）**：入站方向/认证守卫、`job.create` ack 与幂等、deny 闭环、revoke 真撤销、mock companion 对齐 needs_permission 路径；`npm run e2e:real-companion` 覆盖 deny/allow/方向断言。真机 phone 矩阵见 [phone联调验收矩阵.md](../共同维护/计划/phone联调验收矩阵.md)，自动化项见矩阵 `[auto]` 标注。
- **Phone 对接设计（2026-08）**：电话端不做屏幕 UI；张老板经自然对话调用 16 个 companion FC，覆盖发现/准备/确认连接、只读探索、正式委派、用户验收关闭与后台回电。详见 [电话侧张老板连接事务闭环设计.md](../共同维护/技术设计/电话侧张老板连接事务闭环设计.md)。
- **Wave 7（2026-08）**：`job.create` 事务化（apply 成功才 ack）；revoke 停 delegator + 清 connection；session 单活；delegator in-flight 锁 + allow_once 延后消耗 + apply/send 拆分；启动 `reconcileDelegatorOnStartup`；入站 identity 绑定；`job.cancel` 终态/不存在幂等 ack；supervision 无 phone 时不 `phone_unknown` 广播；mock scope 校验。
- `packages/openclaw-adapter`：create/read/cancel job API；mock runtime 与 `createLocalSafeRuntimeClient`。真实 Gateway 仍为轮询 + 向 phone 推协议事件，不接 OpenClaw 原生 event stream。
- OpenClaw 接入路线见 [OpenClaw勘探记录.md](./OpenClaw勘探记录.md)。自托管基线见 [OpenClaw自托管与捆绑.md](../共同维护/技术设计/OpenClaw自托管与捆绑.md)。
- 控制面板 UI 契约示例位于 `examples/control-panel/`；任务/权限/张老板协议示例如 `examples/说明.md`。

## 实施阶段

1. Protocol 与 security contract。
2. 本地 mock bridge 与 schema validation。
3. Companion pairing 与 permission UI。
4. OpenClaw adapter job API + local-safe 只读实跑（Gateway 端到端仍待）。
5. 澜星电话接入与张老板 affair loop。

## 验证策略

- Protocol docs：examples 必须匹配 JSON Schema。
- Protocol package：覆盖 validation 和 state transition 的 unit test。
- Companion：覆盖 pairing、permissions、reconnect、blocked jobs、low-risk job 编排的 integration / contract test（`npm run test -w @lanxin-claw/companion`）。
- OpenClaw adapter：mock runtime + local-safe contract test（`npm run test -w @lanxin-claw/openclaw-adapter`），并接入 `npm run quality`。

## 产品 V1.0 收尾实现（2026-09-11）

- 协议 0.2：迁移表由 protocol 生成 phone JSON；关联回执、即时完成顺序、关闭命令/结果见 [收尾合同](../共同维护/技术设计/协议/v0.2收尾合同.md)。
- `affairs/actions/` 统一 UI/WS 关闭；持久化 pending 围栏、同事务串行队列、完整停止证据及重启恢复。
- `backend/jobs/create.ts` 原子登记新 job 与 currentJobId；旧 job 事件不能抢占，未停止执行任务不能被替换。
- `jobs/delegation/polling/` 保留未成功提交的 job/事务投影，终态结果重试时不再请求 runtime。
- `protocol-server/message-outbox.ts` 与 `backend/chat/message-receipts.ts` 管理原消息、收件身份和消费证明；桌面自由文本不继承事务。
- quality 包含 typecheck 和 strict structure；原 25 长度告警已拆分，当前门禁为 0 errors/0 warnings。实机结果以 [收尾计划](../共同维护/计划/v1.0/产品收尾计划.md) 台账为准。
- 自托管启动隔离父环境凭据、固定 Qwen provider 兼容组件，并等待真实模型探针；取消须匹配 abort 回执后读取同一 run 的终态。Pi/Gateway/Electron 的读文件、关闭恢复、消息交付、回电状态链和托盘退出已验收；物理音频/GPIO 未在本轮复验。phone 锁定 613ae1a；桌面保留待提交工作区，见收尾台账。
