# OpenClaw 集成

## 边界声明

OpenClaw 是 execution engine。澜星负责 desktop shell、phone bridge、pairing、permissions、affair model 与张老板交互。

默认集成策略：

1. 优先使用 public extension points。
2. 优先使用 adapter process 或 package，而不是 patch core files。
3. 只有不存在稳定 extension point 时，才 patch OpenClaw core。
4. Patch 必须小、可记录、upstream-friendly。

## Adapter 职责

OpenClaw adapter 接收 Lanxing job，并将其翻译成 OpenClaw work。

它负责报告：

- accepted
- progress
- needs_permission
- blocked
- completed
- failed
- canceled

它不得决定 affair 是否 closed。只有张老板 affair layer 可以在 user acceptance 之后把 affair 移到 accepted/closed。

## 状态映射补充

OpenClaw 的 run、task、tool、audit、history 都只能证明 execution engine 侧事实，不能直接证明 Lanxin affair 完成。

Adapter 状态推进必须遵循携证规则：

- `agent` 返回 accepted/runId 只证明 OpenClaw 已接受执行，可推进 Lanxin job 到 `running`。
- `agent.wait.status = "ok"` 只证明 agent loop 正常结束，不能单独证明用户目标完成。
- `agent.wait.status = "timeout"` 可能只是等待窗口超时，也可能是 run terminal timeout；没有 `endedAt`、audit/task terminal timeout 或 lifecycle terminal 证据时，保持观察，不写终态失败。
- audit/tool 的 blocked、failed、timed_out、cancelled 是强证据，可推进 Lanxin job 到 `blocked/failed/canceled`。
- task ledger 是后台任务账本，不保证每个 run 都有 task；task `completed` 不能单独证明 job 或 affair 完成。
- final assistant text 只能作为用户可读摘要或弱阻塞证据，不能单独升级为成功。

## 禁止耦合

- 不把张老板 prompts 或 personality rules 嵌入 OpenClaw core。
- 不让 OpenClaw 拥有 pairing 或 phone identity。
- 不让 OpenClaw 静默扩大 permissions。
- 不让 phone protocol message 绕过 companion permission gate。
