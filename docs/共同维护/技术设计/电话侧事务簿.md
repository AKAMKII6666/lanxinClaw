# 澜星电话侧 Affair Store 设计

> 适用范围：v1.3 P7。本文是电话侧事务簿的工程设计真源。  
> 协议对象与状态机仍以 [协议/事务.md](协议/事务.md)、`schemas/affair.schema.json`、`packages/protocol` 为准。  
> 本仓库不实现澜星电话主仓；本文约束电话侧落库形状与边界，供主仓接入时遵守。

## 1. 目标与非目标

### 目标

- 挂电话后 affair 仍可从本地 store 恢复，张老板能回答“上次那个活儿到哪了”。
- Store 是电话侧事务真相源；companion 镜像与 job 事件是同步输入，不能反向关闭 affair。
- 生命周期与协议 `affair.status` 一致；`job.completed` 只推进到 `waiting_acceptance`，不得写 `closed`。

### 非目标

- 不在电话端执行电脑文件、命令、git、网络副作用。
- 不把 OpenClaw run 状态直接当 affair 终态。
- 不把 API key、pairing secret、token、私钥写入 store 或日志。
- 不替代 companion 权限裁决。

## 2. Owner 与信任边界

```text
张老板 / 电话侧 Affair Store
  拥有：affair 连续性、验收前状态、本地时间线、监督游标
Companion
  拥有：配对、权限、job 委派与桌面副作用门禁
OpenClaw Adapter / Runtime
  拥有：worker 执行细节；不拥有 affair.closed
```

| 数据 | Owner | 说明 |
|------|-------|------|
| Affair 记录与状态迁移 | 电话侧 store | 关闭须用户接受或明确取消 |
| Job 进度镜像 | 电话侧 store（只读镜像） | 来自 `job.*` 事件；不得绕过 companion 改桌面 |
| Permission 决策 | companion | store 只记知情摘要，不存授权权威 |
| 凭据 | companion OS secure storage | store **禁止**落凭据 |

## 3. Store Schema

### 3.1 根文档 `AffairStoreRoot`

```json
{
  "schemaVersion": 1,
  "ownerAgent": "zhang-boss",
  "updatedAt": "2026-07-23T00:00:00.000Z",
  "activeAffairId": null,
  "affairs": {}
}
```

| 字段 | 类型 | 含义 |
|------|------|------|
| `schemaVersion` | number | store 文件格式版本；破坏性变更递增 |
| `ownerAgent` | `"zhang-boss"` | 与协议 Affair 一致；禁止写成 openclaw |
| `updatedAt` | ISO-8601 string | 根文档最近写入时间 |
| `activeAffairId` | string \| null | 当前通话或后台监督聚焦的 affair |
| `affairs` | map | `affairId` → `StoredAffair` |

### 3.2 记录 `StoredAffair`

协议 Affair 字段为必选镜像；电话侧扩展字段不得出现在未约定的 phone→companion 载荷里（同步时只发协议字段）。

```json
{
  "affairId": "affair_01H...",
  "title": "Fix the xxx project code issue",
  "ownerAgent": "zhang-boss",
  "status": "running",
  "context": ["The project is on drive F."],
  "acceptanceCriteria": ["Tests pass.", "The user accepts the result."],
  "blockedReason": null,
  "resumeCondition": null,
  "currentJobId": "job_01H...",
  "createdAt": "2026-07-23T00:00:00.000Z",
  "updatedAt": "2026-07-23T00:05:00.000Z",
  "lastSyncedAt": "2026-07-23T00:05:00.000Z",
  "pairedDesktopDeviceId": "desktop_01H...",
  "supervision": "background",
  "callSessionId": null,
  "revision": 3,
  "jobs": {
    "job_01H...": {
      "jobId": "job_01H...",
      "status": "running",
      "goal": "Inspect and fix until tests pass.",
      "progressSummary": "Running tests",
      "blockedReason": null,
      "resumeCondition": null,
      "updatedAt": "2026-07-23T00:05:00.000Z"
    }
  },
  "timeline": [
    {
      "at": "2026-07-23T00:01:00.000Z",
      "kind": "status_change",
      "from": "ready",
      "to": "delegated",
      "note": "created job_01H..."
    }
  ],
  "pendingContext": []
}
```

#### 协议镜像字段（与 `affair.schema.json` 对齐）

`affairId`、`title`、`ownerAgent`、`status`、`context`、`acceptanceCriteria`、`blockedReason`、`resumeCondition`、`currentJobId`。

#### 电话侧扩展字段

| 字段 | 含义 |
|------|------|
| `createdAt` / `updatedAt` | 本地创建与最近变更时间 |
| `lastSyncedAt` | 最近一次成功与 companion 同步的时间；断线后可据此追事件 |
| `pairedDesktopDeviceId` | 该事务绑定的已配对桌面身份；重连按 identity，不按 IP/端口 |
| `supervision` | `active_call` \| `background`：通话中或挂机后台盯梢 |
| `callSessionId` | 可选；关联电话通话会话，挂机后置 null，affair 仍保留 |
| `revision` | 本地单调版本；冲突时以更高 revision + 合法状态迁移为准 |
| `jobs` | job 镜像表；只反映 companion/adapter 汇报 |
| `timeline` | 已尝试步骤与状态变化；供张老板复述与控制面板后续对齐 |
| `pendingContext` | 尚未被张老板消费的 `chat.context_attach` 摘要（文本按 untrusted 处理） |

### 3.3 时间线条目 `TimelineEntry`

| `kind` | 用途 |
|--------|------|
| `status_change` | affair 状态迁移 |
| `job_event` | 收到 `job.*` |
| `context_attach` | 收到精确文本附加 |
| `user_note` | 用户口头补充写入 context |
| `supervision` | 监督 loop 决策摘要（低打扰；不含凭据） |

禁止在 `note` / `progressSummary` / `pendingContext.text` 中写入 API key、token、私钥或完整 secret。

## 4. 生命周期

### 4.1 与协议状态机对齐

合法迁移以 `packages/protocol` 的 `canTransitionAffairStatus` 为准：

| 从 | 可到 |
|----|------|
| `clarifying` | `ready`、`canceled` |
| `ready` | `delegated`、`clarifying`、`canceled` |
| `delegated` | `running`、`blocked`、`paused`、`canceled` |
| `running` | `blocked`、`paused`、`waiting_acceptance`、`canceled` |
| `blocked` | `running`、`paused`、`canceled` |
| `paused` | `running`、`blocked`、`canceled` |
| `waiting_acceptance` | `closed`、`running`、`canceled` |
| `closed` / `canceled` | （终态，无出边） |

硬约束：

- 不存在 `running` → `closed` 或 `job.completed` → `affair.closed` 的合法路径。
- `job.completed` → store 将 affair 标为 `waiting_acceptance`，并写 timeline。
- 仅用户明确验收后 `affair.close`（status=`closed`），或用户明确取消（`canceled`）。

### 4.2 通话与挂机

```text
通话中 clarifying/ready
  -> 创建 affair（写入 store，supervision=active_call）
  -> 可选 affair.create 镜像到 companion
  -> 创建 job（job.create）后 status=delegated/running
用户挂电话
  -> callSessionId=null，supervision=background
  -> store 保留全部字段；不删除、不自动 closed
后台
  -> 消费 job.progress / blocked / completed
  -> blocked 时保留 blockedReason 与 resumeCondition
用户再接通或打开控制面板
  -> 从 store 恢复 activeAffairId 与 timeline
```

### 4.3 同步规则

| 事件 | Store 行为 |
|------|------------|
| 本地创建 / 澄清完成 | 先写 store，再发 `affair.create` / `affair.update` |
| `job.accepted` / `progress` | 更新 `jobs` 镜像表（`jobId` → job）与 `currentJobId`；affair 可到 `running` |
| `job.blocked` | job + affair → `blocked`；抄写 reason / resumeCondition |
| `job.completed` | job → `completed`；affair → `waiting_acceptance` |
| `job.failed` | job → `failed`；affair 通常 → `blocked`（由张老板决策） |
| `affair.resume` 成功回执 / 后续 progress | `blocked`/`paused` → `running` |
| 断线重连 | 按 `pairedDesktopDeviceId` + session 认证恢复；用 `affairId`/`jobId` 去重，禁止盲目重放高风险写 |

幂等键：`affairId`、`jobId`、时间线可附 `messageId`。重复事件不得造成二次委派或二次关闭。

## 5. 持久化路径

电话侧实现落在澜星电话主仓；本设计规定**逻辑路径与安全属性**，具体 OS API 由主仓选型。

### 5.1 推荐布局

```text
{app_private_data}/lanxin-claw/
  ├── store-meta.json          # schemaVersion、迁移游标
  ├── affairs/
  │   ├── index.json           # AffairStoreRoot（或等价 DB 索引）
  │   └── {affairId}.json      # 单条 StoredAffair（可选拆分）
  └── tmp/
      └── *.partial            # 原子写入临时文件
```

| 项 | 要求 |
|----|------|
| 位置 | 应用私有目录；不进共享相册/下载目录/可被其它 App 读取的路径 |
| 编码 | UTF-8 JSON；或等价 SQLite（表字段与本节 schema 同构） |
| 原子性 | 写 temp → fsync → rename；崩溃不得留下半截权威文件 |
| 备份 | 可进系统加密备份；导出调试包前必须脱敏 |
| 删除 | `closed`/`canceled` 可在保留期后归档；归档仍禁止含凭据 |

### 5.2 禁止落盘

- API key、Gateway token、pairing secret、设备私钥
- 完整桌面绝对路径若被策略标为敏感，可只存用户已明确提供的 path 字符串（仍视为 untrusted context）
- OpenClaw 内部 transcript 全量（如需诊断，只留摘要 id）

## 6. 读写 API（电话进程内）

设计级接口；主仓可用任意语言实现，语义须一致。

| 操作 | 语义 |
|------|------|
| `upsertAffair(record)` | 校验状态迁移后写入；bump `revision` |
| `getAffair(affairId)` | 返回 StoredAffair 或空 |
| `listAffairs(filter)` | 按 status / supervision 过滤 |
| `appendTimeline(affairId, entry)` | 追加已尝试步骤 |
| `mirrorJobEvent(event)` | 应用 `job.*`；completed 时只到 `waiting_acceptance` |
| `setSupervision(affairId, mode)` | 挂机切 `background` |
| `enqueuePendingContext(attach)` | 保存 untrusted 精确文本，供 FC fallback 消费 |

所有写操作失败必须可诊断，且不得部分提交后宣称已 closed。

## 7. 与后续任务的边界

| 后续任务 | 本设计已覆盖 | 留给后续 |

| 控制面板任务详情 | timeline / blocker / resume 字段可投影 | UI 实现 |

## 8. 验收清单

- 挂电话后重新打开事务簿，同一 `affairId` 状态与 timeline 仍在。
- Store 中 `ownerAgent` 恒为 `zhang-boss`。
- 任意 `job.completed` 路径下 affair 不得直接变为 `closed`。
- 持久化目录在应用私有空间；抽样检查无凭据明文。
- 状态迁移与 `canTransitionAffairStatus` 一致；非法迁移被拒绝并保留旧值。
