# 阻塞沟通策略

本文定义 companion / 张老板在 affair 进入 `blocked` 时如何低打扰地通知用户。

## 目标

- 用户能立刻知道：谁卡住了、为什么、需要谁处理、如何 resume。
- 不因轮询抖动或重复 progress 反复打扰。

## 触发规则

| 条件 | 动作 |
|------|------|
| 首次进入 blocked | 允许发出一次阻塞通知（call 或 chat.message） |
| 同一 `affairId` + 同一 `resumeCondition` 指纹 | 抑制重复通知，仅更新面板 |
| `resumeCondition` 变化 | 允许再发一次（说明新恢复条件） |
| 用户主动打开控制面板 | 不发通知，只展示当前 blocker |
| affair 已 paused / waiting_acceptance / closed / canceled | 不发阻塞通知 |

指纹建议：`affairId + "|" + (resumeCondition ?? "") + "|" + (blockedReason 摘要)`。

## 文案模板

面向用户的中文文案，技术标识可保留英文。

```text
标题：事务卡住了，需要你看一下
正文：
我这边让 Claw 推进「{affairTitle}」时停住了。
原因：{blockedReason}
已尝试：{attemptedStepsSummary}
恢复条件：{resumeCondition}
你处理好后告诉我，或在控制面板点「恢复」。
```

禁止：

- 假装底层执行一定正确。
- 把 worker completed 说成事务已关闭。
- 文案中夹带 API key、token、私钥。

## Owner

- companion `supervision` 模块负责判定是否应通知、生成文案。
- 电话侧张老板决定用通话还是文字触达用户；companion 不强制开麦。
- UI 只展示；不得绕过 companion 自行“解决”阻塞副作用。
