# 日志系统设计

> 适用范围：companion 桌面壳与自托管 OpenClaw 运行时。
> 目的：按模块分文件落盘，让 LLM Agent 在排障时按问题域定位日志，避免一次性加载整目录。

## 1. 目标与非目标

### 目标

- 所有 Node 侧日志统一经 pino 落盘，JSON lines，便于程序化过滤。
- 按子系统分模块文件，一个模块一个文件，error 级另聚合到 `error.log`。
- 凭据类字段（pairingSecret / authProof / token / apiKey / challenge 等）一律脱敏。
- 提供 `logs:ls` / `logs:tail` 两个入口，供 Agent 按模块按行取日志。

### 非目标

- 不替换 renderer 内部状态管理；renderer 只经 bridge 上报日志。
- 不做全文检索/可视化（按需由 Agent 工具读取）。

## 2. 模块划分

| 模块 | 文件名 | 记录内容 |
|------|--------|----------|
| `system` | system.log | 进程启动、生命周期、全局错误 |
| `protocol` | protocol.log | 协议 envelope 校验、入站/出站消息摘要（只记 id 与状态） |
| `discovery` | discovery.log | mDNS 广告/浏览、发现事件 |
| `adapter` | adapter.log | JobDelegator 委派、adapter create/read/cancel、轮询 |
| `supervision` | supervision.log | 监督 tick、blocked 通知、验收决策 |
| `audit` | audit.log | 权限审计摘要（不记凭据） |
| `bridge` | bridge.log | renderer bridge 通道、错误上报 |
| `shell` | shell.log | Electron 壳装配、启动/退出 |
| `transport` | transport.log | WS 传输层帧级别摘要（不含 payload 明文） |
| `ui` | ui.log | renderer 经 `lanxin:bridge:log` 上报的日志 |
| `runtime` | runtime.log | 自托管 OpenClaw 子进程 stdout/stderr 转发 |
| `error`（聚合） | error.log | 所有模块 error 级行 |

## 3. 目录与轮转

- 日志目录解析顺序：`LANXIN_LOG_DIR` → Electron `userData/logs` → `<repo>/runtime/logs`。
- 单文件按大小轮转（默认 10MB），保留最近 7 个文件（当前文件 + 6 个轮转）。
- 文件名由 pino-roll 追加序号：`<module>.log.1` 为当前活动文件，轮转递增。

## 4. 脱敏

以下字段路径在 pino redact 中统一替换为 `[REDACTED]`：

`pairingSecret`、`authProof`、`token`、`apiKey`、`api_key`、`authorization`、`challenge`、`password`、`secret`（含 `*.field` 与 `**.field` 任意层级）。

审计、协议与示例日志只记录 id 与状态摘要，禁止完整凭据、私钥或 token 明文。

## 5. renderer 日志

- 通道：`lanxin:bridge:log`（只读上报，不是操作意图，不进 action-guard）。
- 白名单：module 仅允许 `ui`；level ∈ `debug/info/warn/error`；message ≤ 2000 字符；meta 序列化深度 ≤ 3。
- renderer 无法伪造其它模块日志；落盘时仍经 pino redact。

## 6. Agent 使用方式

```bash
# 列出各模块文件与大小
npm run logs:ls

# 取 adapter 模块最近 100 行
npm run logs:tail -- --module adapter --lines 100

# 取某时间之后的协议日志（pretty 人读模式）
npm run logs:tail -- --module protocol --since 2026-08-16T08:00:00Z --pretty
```

排障建议：先 `logs:ls` 看各模块大小与更新时间，再按问题域 `logs:tail` 定位；error 级问题直接看 `error.log`。
