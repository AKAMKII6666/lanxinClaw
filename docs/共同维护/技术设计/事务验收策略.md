# 事务验收策略

本文定义 worker `completed` 之后，affair 如何进入与离开 `waiting_acceptance`。

## 硬边界

- Worker / OpenClaw `completed` **不得**自动映射为 affair `closed`。
- 事务关闭必须等待：用户明确接受，或用户/张老板明确取消。
- Renderer 只提交意图；关闭权威在 companion backend / 电话侧事务簿，经协议消息落地。

## 状态流

```text
running / delegated
  -> job.completed（或等价完成事件）
  -> affair.waiting_acceptance
  -> 用户接受 -> affair.close(status=closed)
  -> 用户拒绝继续 / 明确取消 -> affair.close(status=canceled) 或回到可再委派非终态
```

## 用户可见文案

待验收：

```text
Claw 说这轮活干完了。请你确认是否达到完成标准；确认后我才把事务关掉。
```

接受后：

```text
你已确认验收，事务关闭。
```

取消：

```text
你选择不按完成关闭；事务已取消（或保留以便再委派），不会假装已经验收通过。
```

## 控制面板

- 任务详情必须展示：完成标准、已尝试步骤、当前是否 `waiting_acceptance`。
- 「请求验收」只是催促用户看结果，不是自动 closed。
- 「关闭 / 接受」必须产生可审计记录（谁、何时、对哪个 affair）。
