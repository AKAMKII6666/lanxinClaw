# 目录落点

本文是文件落点真源。

目标不是追求抽象优雅，而是在平铺目录、模糊 utility 桶、隐藏 owner 漂移变成常态之前把它们挡住。

## 顶层结构

```text
.
├─ apps/
│  └─ companion/
├─ packages/
│  ├─ protocol/
│  └─ openclaw-adapter/
├─ scripts/
│  └─ quality/
├─ schemas/
├─ examples/
│  ├─ control-panel/   # 总览 / 权限队列 / 诊断 UI 契约正例
│  ├─ tasks/           # 任务页相关协议 envelope
│  ├─ permissions/     # 权限协议 envelope
│  └─ zhang-boss/      # 张老板入口 chat / context_attach
├─ docs/
│  ├─ 人类维护/
│  ├─ 共同维护/
│  │  ├─ 需求/
│  │  ├─ 技术设计/
│  │  ├─ 计划/
│  │  └─ 决议/
│  └─ 智能体维护/
└─ .cursor/rules/
```

仓库根使用 npm workspaces（`apps/*`、`packages/*`）与共享 `tsconfig.base.json`。示例索引见 [examples/说明.md](../../../examples/说明.md)。

## Package 结构

`packages/protocol/` 负责 shared protocol types、schemas、validators、state machines、ids 和 errors。

```text
packages/protocol/
  src/
    messages/
    schemas/
    validators/
    states/
    errors/
    ids/
    index.ts
  tests/
```

`packages/openclaw-adapter/` 负责 Lanxing jobs 与 OpenClaw execution 之间的翻译。

```text
packages/openclaw-adapter/
  src/
    client/
    jobs/
    status/
    mapping/
    index.ts
  tests/
```

`apps/companion/` 负责 desktop shell、phone bridge、pairing、credentials、permissions、jobs、chat 和 UI。

```text
apps/companion/
  src/
    bridge/
    pairing/
    permissions/
    credentials/
    jobs/
    chat/
    ui/
  tests/
```

## Barrel 规则

- Package public entrypoint 可以使用 `src/index.ts`。
- UI component 目录可以使用 `ComponentName/index.tsx` 作为组件入口。
- 内部目录不得使用 `index.ts` 或 `index.tsx` 作为 re-export barrel。
- 移动文件必须同步更新 import 并删除旧路径。默认不允许 compatibility forwarding file。

## 测试

测试放在 package 或 app 的 `tests/` 目录中。不得把 `*.test.ts`、`*.test.tsx`、`*.spec.ts`、`*.spec.tsx` 与源码平放。

## 目录聚类

同一目录内源文件达到 4 个且职责组达到 2 个时，必须拆子目录。

长文件名前缀不能替代目录。例如下面这种不可接受：

```text
src/
  pairingServer.ts
  pairingStore.ts
  jobRunner.ts
  permissionDialog.ts
  credentialVault.ts
```

应改为：

```text
src/
  pairing/
  jobs/
  permissions/
  credentials/
```
