# 协议消息目录

本文是 runtime 协议 message type 的总目录。分区细节仍以各专题文档为准；新增或修改 type 时必须同步本文、对应专题文档与 `schemas/`。

Discovery 使用 mDNS / DNS-SD 广告，不走 envelope，故不列入本目录。本目录只覆盖 WebSocket（或等价）会话上的 envelope message。

## 通用约定

| 项 | 约定 |
|----|------|
| Envelope | 见 [消息格式.md](消息格式.md)；`protocolVersion` 当前为 `0.1` |
| 认证 | `none`：未配对可发；`pairing`：配对流程内；`session`：须已通过 `session.accepted` |
| 未知 type | 接收方必须安全拒绝或忽略，不得当指令执行 |
| 未知 payload 字段 | 默认可忽略；标为 strict 的 type 除外 |
| 幂等 | 带 `affairId` / `jobId` / `permissionRequestId` 的写操作须可按 id 去重 |
| 入站守卫 | phone→companion 业务消息须 `source.kind=phone` 且 `target.kind=companion`；companion→phone 类型不得作为 phone 入站；未认证 socket 仅允许 `session.open`（配对完成后） |
| 出站 apply | companion 广播前须 backend apply 成功；非法状态迁移不得 send |
| 兼容策略 | `0.1` 为 draft，允许破坏性变更；变更须同步 docs 与 schema |

## Pairing

### `pairing.request`

| 项 | 内容 |
|----|------|
| 方向 | phone → companion |
| 认证 | `none`（发现后、配对前） |
| Payload | `pairingId`、`phoneDeviceId`、`phoneDisplayName`、`protocolVersion`、`capabilities` |
| 错误行为 | companion 不可用或拒绝发现时回 `pairing.revoked` 或带 `error` 的关闭；不得因此授予 session |
| 兼容策略 | 未知 capability 可忽略；缺少必填字段则拒绝 |

### `pairing.challenge`

| 项 | 内容 |
|----|------|
| 方向 | companion → phone |
| 认证 | pairing 流程内；`correlationId` 指向 `pairing.request` |
| Payload | `pairingId`、`desktopDeviceId`、`desktopDisplayName`、`challenge`、`expiresAt` |
| 错误行为 | challenge 过期后 phone 须重新 `pairing.request`；不得复用过期 challenge |
| 兼容策略 | 未知字段可忽略 |

### `pairing.confirmed`

| 项 | 内容 |
|----|------|
| 方向 | phone → companion |
| 认证 | pairing；须含 challenge 应答 |
| Payload | `pairingId`、`challengeResponse`、`phoneConfirmedAt` |
| 错误行为 | 应答错误则配对失败，两端回到 `unpaired`；不得建立 session |
| 兼容策略 | strict：未知必填替代字段不得 silently 成功 |

### `pairing.desktop_approved`

| 项 | 内容 |
|----|------|
| 方向 | companion → phone |
| 认证 | pairing；桌面用户已确认 |
| Payload | `pairingId`、`desktopApprovedAt` |
| 错误行为 | 桌面拒绝则发 `pairing.revoked` 或等价失败，不得发 `pairing.completed` |
| 兼容策略 | 缺少桌面确认不得 completed |

### `pairing.completed`

| 项 | 内容 |
|----|------|
| 方向 | companion → phone |
| 认证 | pairing 双确认均已完成 |
| Payload | `pairingId`、`phoneDeviceId`、`desktopDeviceId`、`pairingSecret`、`pairedAt` |
| 错误行为 | 仅表示身份信任建立；**不**授予执行权限；`pairingSecret` 只用于后续 `session.open` HMAC，必须脱敏保存与日志 |
| 兼容策略 | 成功后两端持久化 device identity |

### `pairing.revoked`

| 项 | 内容 |
|----|------|
| 方向 | either |
| 认证 | 已配对 session，或配对流程中任一方取消 |
| Payload | `pairingId`（可空）、`phoneDeviceId`、`desktopDeviceId`、`reason`、`revokedAt` |
| 错误行为 | 接收方必须立刻失效 session，拒绝后续需 session 的消息 |
| 兼容策略 | 重复 revoke 幂等成功 |

## Session

### `session.open`

| 项 | 内容 |
|----|------|
| 方向 | phone → companion |
| 认证 | 已配对 identity；用 proof 证明持有配对密钥 |
| Payload | `sessionId`、`phoneDeviceId`、`desktopDeviceId`、`authProof`、`protocolVersion` |
| 错误行为 | 证明失败回 `session.reauth_required` 或拒绝；不得因端口存在而接受 |
| 兼容策略 | 未知字段可忽略；**新 session.open 成功时 companion 仅保留单活 authenticated socket**（旧 socket 终止） |

### 入站 identity 绑定（业务消息）

| 项 | 内容 |
|----|------|
| 范围 | 已认证 session 下的 affair/job/chat/permission 入站 |
| 校验 | `source.deviceId` 须等于 `connection.phoneDeviceId`；`target.deviceId` 须等于 companion `desktopDeviceId` |
| 错误行为 | 不匹配 → `inbound_identity_mismatch`，不写入 store |

| 项 | 内容 |
|----|------|
| 方向 | companion → phone |
| 认证 | session 握手中 |
| Payload | `sessionId`、`acceptedAt`、`heartbeatIntervalMs` |
| 错误行为 | 接受后才允许 affair/job/chat/permission |
| 兼容策略 | `0.1` 可调整 heartbeat 默认值 |

### `session.heartbeat`

| 项 | 内容 |
|----|------|
| 方向 | either |
| 认证 | session |
| Payload | `sessionId`、`sentAt`、`seq`（可选） |
| 错误行为 | 超时未收到可本地标记断开，但不得丢弃 in-flight affair/job id |
| 兼容策略 | 可忽略未知字段 |

### `session.closed`

| 项 | 内容 |
|----|------|
| 方向 | either |
| 认证 | session |
| Payload | `sessionId`、`reason`、`closedAt` |
| 错误行为 | 优雅关闭；重连后用原 id 恢复 in-flight 工作，禁止盲目重放高风险写操作 |
| 兼容策略 | 重复 close 幂等 |

### `session.reauth_required`

| 项 | 内容 |
|----|------|
| 方向 | companion → phone |
| 认证 | 当前凭证不足或已吊销 |
| Payload | `sessionId`（可空）、`reason`、`requiredAction`（`reopen` / `repair`） |
| 错误行为 | phone 必须停止发送需 session 的业务消息，直到重新 `session.open` 或重新配对 |
| 兼容策略 | 未知 `requiredAction` 按 `reopen` 处理 |

## Affair

Payload 主体为 Affair 对象（见 schema）。`affair.create` / `affair.update` 可带完整对象；`affair.resume` / `affair.close` 至少带 `affairId` 与目标 status 相关字段。

### `affair.create`

| 项 | 内容 |
|----|------|
| 方向 | phone → companion |
| 认证 | session |
| Payload | Affair 对象；`status` 通常为 `clarifying` 或 `ready` |
| 错误行为 | 缺 `affairId` / title / criteria 则拒绝；重复同 id 按幂等合并或拒绝冲突 |
| 兼容策略 | 未知可选字段可忽略 |

### `affair.update`

| 项 | 内容 |
|----|------|
| 方向 | either |
| 认证 | session |
| Payload | 含 `affairId` 的 Affair 局部或完整更新 |
| 错误行为 | 非法状态迁移须拒绝并保留旧状态；不得把 `waiting_acceptance` 静默改成 `closed` |
| 兼容策略 | 只应用已知字段 |

### `affair.resume`

| 项 | 内容 |
|----|------|
| 方向 | phone → companion |
| 认证 | session |
| Payload | `affairId`、可选 `resumeNote`；期望从 `blocked` / `paused` 恢复 |
| 错误行为 | resume condition 未满足则保持 `blocked`/`paused` 并说明原因 |
| 兼容策略 | 未知字段可忽略 |

### `affair.close`

| 项 | 内容 |
|----|------|
| 方向 | phone → companion |
| 认证 | session |
| Payload | `affairId`、`status`=`closed` 或 `canceled`、可选 `closeReason` |
| 错误行为 | **禁止**因 `job.completed` 自动 close；须用户接受或明确取消 |
| 兼容策略 | 已 closed 再 close 幂等 |

## Job

Payload 主体为 Job 对象。`job.completed` **不等于** affair `closed`。

### `job.create`

| 项 | 内容 |
|----|------|
| 方向 | phone → companion |
| 认证 | session |
| Payload | Job 对象；`status` 通常为 `queued`；须含 `affairId`、`goal`、`allowedPermissions`；`purpose` 可为 `execution` 或 `exploration`，默认 `execution` |
| 错误行为 | 未配对 session、`affairId` 不存在、缺 id、或权限预检失败则拒绝；**backend apply 任一步失败则 gate 回滚且不 ack**；不得绕过 companion 直接打 OpenClaw |
| 成功响应 | **须** `job.needs_permission` 与 `permission.request` 均 apply 成功后才返回 `{ ok: true, acceptedType: "job.create" }`；随后 WS 发送上述出站（若已配对 phone） |
| 幂等 | 同 `messageId` 或等价 `jobId` 重放 → `{ ok: true, duplicate: true }`，不重复入队；**同 jobId 并发** → `job_create_in_flight` |
| 兼容策略 | 未知 permission id 不得默默当成已授权 |

### `job.accepted`

| 项 | 内容 |
|----|------|
| 方向 | companion → phone |
| 认证 | session |
| Payload | Job；`status`=`queued` 或 `running` |
| 错误行为 | 接受只表示 companion 已收工；尚未表示 worker 完成 |
| 兼容策略 | 可附加 `correlationId` 回指 `job.create` |

### `job.progress`

| 项 | 内容 |
|----|------|
| 方向 | companion → phone |
| 认证 | session |
| Payload | Job；更新 `progressSummary` 与 `status`=`running` |
| 错误行为 | 进度文案不得含 API key / token / 私钥 |
| 兼容策略 | 可高频；接收方可按 `jobId` 折叠 |

### `job.needs_permission`

| 项 | 内容 |
|----|------|
| 方向 | companion → phone |
| 认证 | session |
| Payload | Job（`status`=`needs_permission`）+ 可选 `permissionRequestId` |
| 错误行为 | 必须伴随或随后发出 `permission.request`；不得在无决策时继续高风险副作用 |
| 兼容策略 | phone 只作知情；授权权威在 companion |

### `job.blocked`

| 项 | 内容 |
|----|------|
| 方向 | companion → phone |
| 认证 | session |
| Payload | Job；须含 `blockedReason`，建议含 `resumeCondition` |
| 错误行为 | 阻塞后停止自动重试高风险动作，直到 resume |
| 兼容策略 | 缺 `resumeCondition` 时 phone/张老板须追问 |

### `job.completed`

| 项 | 内容 |
|----|------|
| 方向 | companion → phone |
| 认证 | session |
| Payload | Job；`status`=`completed` |
| 错误行为 | `purpose=execution` 时 companion/张老板应将对应 affair 推向 `waiting_acceptance`，**不得**自动 `closed`；`purpose=exploration` 只写探索结果，不进入验收 |
| 兼容策略 | 完成摘要不得含凭据明文 |

### `job.failed`

| 项 | 内容 |
|----|------|
| 方向 | companion → phone |
| 认证 | session |
| Payload | Job；`status`=`failed`；建议 `blockedReason` 或等价失败说明 |
| 错误行为 | affair 可转 `blocked` 或保持由张老板决策；不得假装成功 |
| 兼容策略 | 可附 `error` 对象（见消息格式） |

### `job.cancel`

| 项 | 内容 |
|----|------|
| 方向 | phone → companion |
| 认证 | session |
| Payload | 至少 `jobId`、`affairId`；结果 status 期望 `canceled` |
| 错误行为 | 已终态（completed/failed/canceled）则幂等确认；进行中则请求 adapter 取消 |
| 兼容策略 | 重复 cancel 幂等 |

### `job.canceled`

| 项 | 内容 |
|----|------|
| 方向 | companion → phone |
| 认证 | session |
| Payload | Job；`status`=`canceled`，建议含 `statusReasonCode`、`statusObservedAt` |
| Owner | companion；由 adapter 的取消确认或本地未启动取消证据触发 |
| 错误行为 | 不得把 phone 的 `job.cancel` 请求直接当作 OpenClaw 已停止；须等待取消确认或记录“未启动前取消” |
| 兼容策略 | `0.1` draft，无双版本兼容；phone 侧未知时只能忽略，不得继续显示 completed |

## Chat

`chat.message` 与 `chat.context_attach` 的文本均为 **untrusted input**，不得当 system instructions 执行。

### `chat.message`

| 项 | 内容 |
|----|------|
| 方向 | either |
| 认证 | session |
| Payload | `chatMessageId`、`text`、可选 `affairId`、`sentAt`、`authorKind`（`user` / `zhang-boss` / `companion`） |
| 错误行为 | 空文本拒绝；超长可截断或拒绝；不得解析为权限授予 |
| 兼容策略 | 未知字段可忽略 |

### `chat.context_attach`

| 项 | 内容 |
|----|------|
| 方向 | companion → phone |
| 认证 | session |
| Payload | `attachId`、`text`、`target`（`active_call` / `affair`）、可选 `affairId`、`contentKind`（`path` / `log` / `url` / `note`） |
| 错误行为 | `target=affair` 时缺 `affairId` 则拒绝；注入失败须可走 FC fallback，不得静默丢弃而不告知 |
| 兼容策略 | 未知 `contentKind` 按 `note` 处理 |

### `chat.read_receipt`

| 项 | 内容 |
|----|------|
| 方向 | either |
| 认证 | session |
| Payload | `chatMessageId` 或 `attachId`、`readAt` |
| 错误行为 | 可选；缺失不影响业务正确性 |
| 兼容策略 | 可整类忽略 |

## Permission

Companion 是桌面权限权威。Phone 可知情，不可自行授权。

### `permission.request`

| 项 | 内容 |
|----|------|
| 方向 | companion → phone |
| 认证 | session |
| Payload | PermissionRequest 对象（见 schema） |
| 错误行为 | 在用户决策前，companion 不得执行对应高风险副作用；超时未决可保持 `needs_permission` |
| 兼容策略 | 未知 permission id 视为更高风险，默认需确认或拒绝 |

### `permission.decision`

| 项 | 内容 |
|----|------|
| 方向 | companion → phone |
| 认证 | session |
| Payload | `permissionRequestId`、`decision`（`allow_once` / `allow_for_job` / `deny` / `require_more_context`）、`decidedAt`、可选 `note` |
| 错误行为 | `deny` / `require_more_context` 后须广播 `job.failed`（或等价 failed 终态），相关 job 不得继续该权限动作 |
| 兼容策略 | 未知 decision 按 `deny` 处理 |

## 与控制面板的关系

本目录中的 affair / job / permission / session 状态是控制面板任务页、权限页与总览「当前任务 / 待确认」的数据来源。控制面板 snapshot、permission queue、diagnostic report 等 UI 契约见 [控制面板数据契约.md](../控制面板数据契约.md) 与 `schemas/control-panel-*.schema.json`，不在本目录扩展为 phone↔companion 业务 message。

页面所需示例 message 见 [examples/说明.md](../../../../examples/说明.md)：任务页用 `examples/tasks/*`，权限协议面用 `examples/permissions/*`，张老板入口用 `examples/zhang-boss/*`（`chat.message` / `chat.context_attach` 仍为 untrusted input）。
