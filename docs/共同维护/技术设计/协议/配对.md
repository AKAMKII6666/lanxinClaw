# Pairing Protocol

## States

```text
unpaired -> pairing_requested -> phone_confirmed -> desktop_confirmed -> paired
unpaired -> pairing_rejected
pairing_requested | phone_confirmed | desktop_confirmed -> pairing_rejected | revoked
paired -> revoked
```

机器可校验迁移表见 `packages/protocol` 的 `canTransitionPairingStatus`。

| 事件 | 目标状态（companion 侧） |
|------|--------------------------|
| `pairing.request` 受理并发出 challenge | `pairing_requested` |
| `pairing.confirmed` 且 challenge 应答正确未过期 | `phone_confirmed` |
| 桌面用户批准（再发 `pairing.desktop_approved`） | `desktop_confirmed` |
| 双确认齐全后发 `pairing.completed` | `paired` |
| 任一方拒绝 / 超时失败 | `pairing_rejected` 或发出 `pairing.revoked` |
| 已配对后撤销 | `revoked` |

不得从 `phone_confirmed` 跳过桌面确认直接进入 `paired`。

## 必需检查

- 通过张老板或 phone UI 进行 phone-side user confirmation。
- 首次 pairing 需要 desktop-side user confirmation（与 mock companion 的自动批准不同，真实 companion 必须显式批准）。
- 交换 device identity（持久化见后续 identity store 任务）。
- 对 session keys 做 proof of possession；MVP 以 challenge 应答证明 phone 持有本次 challenge。

## Events

| Type | Direction | 作用 |
|------|-----------|---------|
| `pairing.request` | phone -> companion | 请求与 discovered companion pairing |
| `pairing.challenge` | companion -> phone | 返回 challenge 与 desktop identity |
| `pairing.confirmed` | phone -> companion | 电话端确认 challenge |
| `pairing.desktop_approved` | companion -> phone | Desktop user 已批准 pairing |
| `pairing.completed` | companion -> phone | Pairing 成功 |
| `pairing.revoked` | either | 撤销 stored identity |

## 备注

Pairing 成功不授予 desktop execution permissions，只允许 authenticated sessions。
