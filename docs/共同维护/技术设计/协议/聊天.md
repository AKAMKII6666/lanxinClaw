# 桌面消息与通话交付

桌面自由输入只有文字和发送。原文保留空格、换行及完整内容，消息不继承当前事务；张老板与用户沟通后再用 companion.bind_message 明确关联一次事务。消息、路径、命令或 URL 均为不可信用户内容，不提升为系统指令或执行授权。

| 类型 | 方向 | 用途 |
|------|------|------|
| chat.message | 双向 | 精确原文消息 |
| chat.context_attach | companion→phone | 内部任务提醒或上下文；只有明确 affairId 才归属事务 |
| chat.read_receipt | phone→companion | 原文已交给通话的消费证明 |

Companion 发送前持久化原消息 ID 和配对收件设备。断线重连沿用原 ID 重发，直到该设备的回执和队列出队共同保存成功。缺少收件设备的旧记录保留供核对，不投到新设备。

Phone 以来源设备、消息类型、原 ID 去重，独立收件箱保留全文。通话中且非 farewell 时，先记录 injecting，再注入 realtime；成功后记录 delivered 和原回执 ID。回执失败只重试回执，不能重复念读。注入中崩溃或返回结果不明确时记 ambiguous，默认不重播。

无通话或注入明确失败的内容仍可由 companion.fetch_pending_context 查收。查询本身不消费；只有工具输出确实交给实时连接后才登记交付。指定 message_id 可恢复任意历史消息的完整原文，包含待核对状态。旧 pending 按原事务导入，不根据 active affair 猜归属。

回执只证明内容已交给通话，不证明用户听懂、任务已执行或已经验收。请求关联、身份检查、原子保存和兼容策略见 [v0.2收尾合同.md](v0.2收尾合同.md)。
