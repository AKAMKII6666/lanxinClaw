# Session Protocol

## 目标

维护 phone 与 companion 之间的 authenticated runtime connection。

## Transports

首选初始 transport：

- 基于 local network 的 WebSocket。

后续可选：

- 简单 command 使用 HTTPS request/response。
- 非 LAN 场景使用 relay transport。

## Events

| Type | Direction | 作用 |
|------|-----------|---------|
| `session.open` | phone -> companion | 启动 authenticated session |
| `session.accepted` | companion -> phone | Session 已认证 |
| `session.heartbeat` | either | Keepalive 与 latency check |
| `session.closed` | either | Graceful close |
| `session.reauth_required` | companion -> phone | 已存 auth 不再足够 |

## Heartbeat timeout

`session.accepted` 广播 `heartbeatIntervalMs`（companion 默认 5000）。Companion 要求 phone 按该间隔发送 `session.heartbeat`：

- 每个入站 heartbeat 更新 companion 侧 `lastSeenAt`。
- 连续错过 3 个周期未收到 heartbeat 时，companion 将连接标记为失联：会话认证失效（后续业务消息须重新 `session.open`）、记录 `connection_lost`，并向 phone 广播 `session.closed`（`reason=heartbeat_timeout`）。
- 失联不影响 in-flight affair/job：store 保留，重连后按原 id 恢复，禁止盲目重放高风险写。

## Reconnect

Reconnect 必须按 id 保留 in-flight affairs 与 jobs。除非 request 具备 idempotent 语义，否则 reconnect 不得重复执行。
