# Permission Protocol

## 原则

Desktop companion 是 desktop actions 的 permission authority。

电话端可以 request work。Companion 决定该 work 是 allowed、denied，还是 needs user confirmation。

## Permission Request

```json
{
  "permissionRequestId": "perm_01H...",
  "jobId": "job_01H...",
  "requestedPermissions": ["workspace.write", "command.run"],
  "reason": "The job needs to edit project files and run tests.",
  "risk": "medium",
  "proposedScope": {
    "workspaceRoot": "F:/workspace/example",
    "commands": ["npm test"]
  }
}
```

## Decisions

| Decision | 含义 |
|----------|---------|
| `allow_once` | 只允许这一次 exact action |
| `allow_for_job` | 在当前 job scope 内允许 |
| `deny` | 拒绝 request |
| `require_more_context` | 请张老板或 user 澄清 |

## Events

| Type | Direction | 作用 |
|------|-----------|---------|
| `permission.request` | companion → phone | 通知 phone：某 job 正在等待桌面权限确认 |
| `permission.decision` | companion → phone | 通知 phone：用户已做出 allow_once / allow_for_job / deny / require_more_context |

用户选择发生在 companion 本地 UI。Renderer 只提交选择，最终授权落在 companion backend。对外协议由 companion 把结果同步给 phone。

Durable permissions 应该 narrow、visible、revocable。
