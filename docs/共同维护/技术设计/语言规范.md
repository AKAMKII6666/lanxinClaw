# 语言规范

## 原则

本项目的文档和注释默认使用中文，因为维护者的母语是中文。专业名词、协议字段、API 名、文件路径、命令、包名、message type、permission id、状态枚举可以保留英文。

规则目标是降低长期维护成本，不是机械消灭所有英文。

## 必须使用中文的内容

- README、AGENTS、docs、`.cursor/rules` 中的解释性文字。
- 代码文件头职责注释。
- 导出函数、interface、type、字段的说明注释。
- 门禁错误说明和修复建议。
- 用户可见文案。

## 可以保留英文的内容

- 协议字段：`affairId`、`jobId`、`protocolVersion`。
- message type：`affair.create`、`job.blocked`。
- permission id：`workspace.read`、`command.run`。
- 技术名词：OpenClaw、WebSocket、mDNS、JSON Schema、TypeScript、JSDoc。
- 命令和路径：`npm run quality`、`packages/protocol/src/index.ts`。
- 代码标识符和枚举值。

## 注释要求

注释必须解释意图、约束、时序、所有权、可空语义或副作用。不得用英文模板糊弄门禁，例如 `This function does X` 这类复述式注释。

## 门禁

`npm run quality` 会运行 `check:language`，检查文档正文和代码注释是否出现整段英文。门禁允许字段、命令、路径和 code fence 中的英文。
