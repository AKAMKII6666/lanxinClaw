# 原则和规范

本目录沉淀可跨项目复用的复杂系统设计原则。

这里的文档不是某个功能的字段级合同，也不是代码风格清单，而是用于需求分析、方案设计、执行计划和代码审查的高风险判断框架。

## 使用边界

- 当一个状态会驱动副作用、用户决策、权限判断、异步恢复或跨系统回报时，应主动引用本目录原则。
- 当需求只是低风险 UI、局部纯函数、静态文案或一次性脚本时，不应机械套用。
- 若原则与当前项目协议、产品需求或安全规则冲突，应先呈现冲突和风险，再由项目真源裁决。
