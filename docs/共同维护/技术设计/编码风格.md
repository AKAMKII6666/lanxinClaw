# 编码风格

本文指导后续实现。在技术栈完全定下来之前，规则保持保守。

## 默认语言

除非目标 runtime 强制使用其它语言，否则 protocol SDK、companion services 和 adapters 默认使用 TypeScript。

## 模块边界

使用明确 owner 目录：

```text
packages/protocol/          shared protocol types, schemas, validators
packages/openclaw-adapter/  OpenClaw integration only
apps/companion/             desktop shell, bridge, pairing, permissions
```

`packages/protocol` 不得从 `apps/companion` import。

`packages/protocol` 不得 import OpenClaw internals。

## 命名

- Protocol message type 使用 `domain.action`，例如 `affair.create`。
- TypeScript type 使用 `PascalCase`。
- Runtime value 和 function 使用 `camelCase`。
- 文件名使用 `kebab-case.ts`。
- 序列化后的 state name 使用小写 snake_case，例如 `waiting_acceptance`。

## 错误处理

- 通过 wire 返回 typed protocol error。
- 可重试请求必须包含 `retryable`。
- Protocol response 不得暴露 stack trace、secret、API key 或原始 environment variable。

## 副作用

- Filesystem、command、network、git、desktop side effect 必须位于 companion permission check 之后。
- Protocol validator 必须是 pure。
- OpenClaw adapter function 必须接收显式 permissions 与 workspace scope。

## 日志

- 可以记录 ids、states 和安全摘要。
- 默认不得记录 credentials、private keys、包含 secret 的完整 environment values 或完整 prompt payload。
- 只有日志可能离开本机时才需要脱敏用户路径；本地 debug log 可在用户选择后保留路径。

## 测试

从小型 contract test 开始：

- Envelope validation。
- Affair state transition。
- Permission request decision。
- OpenClaw adapter status mapping。
