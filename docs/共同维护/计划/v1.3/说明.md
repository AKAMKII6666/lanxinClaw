# v1.3 计划说明

## 版本目标

v1.3 的目标是把“能执行”升级成“张老板能负责”。

到 v1.2 为止，系统可以发现电脑、配对、授权、把 job 派给 OpenClaw。v1.3 要把这些能力接入澜星电话和张老板事务簿，让事务可以后台推进、阻塞暂停、恢复继续、完成后等待用户验收。

控制面板在本版本从“状态面板”升级为“事务工作台”。用户不仅要看到任务在跑，还要看到张老板已经尝试了什么、为什么卡住、需要谁处理、什么时候可以继续、完成后等待谁验收。

## 对应阶段

| 阶段 | 目标 | 产出 | 完成标准 |
|------|------|------|----------|
| P7 张老板事务接入 | 电话端开始接事务簿 | affair store、FC、后台监督、阻塞/完成回报 | 挂电话后事务仍在，阻塞可恢复，完成进入等待验收 |
| P8 精确文本通道 | 电脑文字补充进入张老板上下文 | chat/context attach 协议 + 张老板页完整体验 | 路径、日志、URL 能从电脑传给实时对话 |
| P9 权限与审计 | 收紧安全边界 | 权限分级、一次性授权、job 授权、审计日志 | 高风险动作不能静默执行，有记录可查 |
| P10 产品化迭代 | 体验打磨 | 安装、托盘、开机启动、自动重连、回电策略 | 日常可用，不需要开发者手动开服务 |

## 范围

- 在澜星电话侧接入 affair store。
- 为张老板增加 companion 相关 FC。
- 实现后台事务监督 loop。
- 实现 blocked、paused、resume、waiting_acceptance 的用户体验。
- 完善控制面板任务详情，让用户能看到目标、标准、尝试记录、阻塞原因、恢复条件和验收状态。
- 完善张老板页，实现电脑端文字 chat 与 context attach。
- 实现权限审计日志。
- 实现回电/提醒策略的最小版本。
- 打磨 companion 常驻体验。

## 非目标

- 不把 OpenClaw 改造成角色化 LLM。
- 不让张老板承诺底层执行一定正确。
- 不允许高风险动作静默执行。
- 不做云端多人协作。
- 不支持任意公网暴露。
- 不把控制面板做成替代 OpenClaw 的完整 IDE。

## 控制面板深化范围

| 页面 | v1.3 要深化 | 完成标准 |
|------|-------------|----------|
| 任务 | 展示事务脉络、已尝试步骤、当前 blocker、resume condition、等待验收 | 用户能回答“这个事到哪了，下一步等谁” |
| 张老板 | 支持当前通话和指定 affair 的 context attach | 路径、日志、URL 能准确进入张老板上下文 |
| 权限 | 展示 audit record 和历史 permission decision | 用户能追溯谁在什么时候允许了什么 |
| 总览 | 将 blocked、waiting_acceptance、waiting_user 显示为优先提醒 | 用户打开面板先看到需要自己处理的事 |
| 诊断 | 将最近错误关联到 affair/job | 用户知道错误影响的是哪件事 |

## v1.3 闭环

```text
用户打电话
  -> 张老板澄清事务
  -> 创建 affair
  -> 用户挂电话
  -> 张老板后台监督 companion/OpenClaw job
  -> 用户可在控制面板补充精确文本
  -> blocked 时暂停并联系用户
  -> 用户解除阻塞后 resume
  -> completed 后回报并等待验收
```

## 验收标准

- 用户挂电话后 affair 状态仍可恢复。
- 张老板能回答“上次那个活儿到哪了”。
- Blocked 状态包含原因、已尝试动作、需要谁处理、resume condition。
- 用户提供路径、日志、URL 时，可以从电脑端 chat 注入上下文。
- 控制面板任务详情能展示已尝试动作、阻塞原因、恢复条件和验收状态。
- 张老板页可以把文字上下文附加到当前通话或指定 affair。
- 高风险 permission request 有确认和 audit record。
- Worker completed 后，affair 进入 waiting_acceptance，不自动 closed。
