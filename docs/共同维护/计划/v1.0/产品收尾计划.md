### B1 类型与门禁

可选属性缺省时不传，保留 exactOptionalPropertyTypes；补充 Electron will-quit 契约及测试替身；renderer 诊断包含 browserProxy；Gateway 读取/取消的可选 context 正确传递。禁止 any、关闭严格检查或 suppress 掩盖错误。

### B2 状态和回执合同

- packages/protocol 是迁移表唯一维护源；生成 phone 携带的 JSON 合同，生成器支持 --check，部署不依赖相邻仓库。
- runtime 确实接收且授权有效后，create/reconcile 统一提交 job.accepted/running，再提交即时终态。异步返回后重新验证父事务、current job、取消门闩。apply 失败返回上层，不发送、不假装成功停跟踪。
- ack 有统一类型/schema/validator；成功、失败和重复响应均以 correlationId 精确关联请求 messageId；带消息类型和错误码。关闭成功回执带已提交事务与相关 job 结果。
- phone 请求先登记再发送，绑定当前连接；断线/超时清理等待器；迟到结果只更新原持久化动作。create_job 和探索也迁移到统一请求接口。
- 协议 0.2 同步常量、schema、validators、examples、mock、docs；不兼容时在业务前明确拒绝并提示配套升级。

### B3 事务动作协调

- UI 和 phone 都调用 companion 的同一协调器；generic affair.update/apply 不能绕过终态门闩。
- 取消按 affair 协调：校验 → 取消围栏 → permission expire → 接管迟到 createRun → 取消全部仍可能执行的子 job → 确认不可执行 → 父 canceled 持久化 → 广播/ack。
- 取消仅 accepted、handler 缺失、runtime 不可用或取消失败时不得假终态；已经完成的 job 保留真实终态。外部已取消效果不回滚，按步骤记录恢复。
- 验收请求携带 acceptanceSummary 和 expectedCurrentJobId，重新检查 waiting_acceptance、当前 execution job、有效完成证据；用专用关闭载荷，禁止旧完整事务快照覆盖新事实。
- acceptAffair/cancelAffair 异步确认，发送不等于业务完成；单独 cancel_job 也不提前镜像 canceled。动作 receipt/话术区分请求、待确认、已提交和失败。
- 已同步桌面的事务离线不得声称双方已关闭。持久化待确认请求，重连复用原请求 ID；服务端持久化幂等结果。相同 affair 的 UI/WS/授权/委派串行协调，heartbeat 独立保活。

### B4 消息闭环

- 张老板页移除内容类型和附加目的地选项；自由文本统一 chat.message，不隐式填写 affairId。任务控制仍带明确对象 ID。
- phone 独立消息收件记录保存原文，以来源设备/消息 ID 去重；无 affairId 保持未绑定，删掉 runtime 与 store 的 active fallback。
- 张老板通话可注入确认，离线/不可注入则保留供查收；内部 companion.bind_message(message_id, affair_id) 经沟通后显式绑定，验证对象和原绑定，不授予执行权限。
- 既有 context_attach 历史归一到消息存储，必要的内部明确事务通知保持关联，不作为用户自由输入类型。
- 保存、交给通话、回执待确认、回执确认独立记录；注入成功持久化证据后发 receipt，失败只补回执。companion 幂等应用并关联 ack；确认后清理发送队列，保留完整原文。
- FC 查收共用消费记录，不直接清空消息；截断仍可取全文；注入中崩溃的模糊结果保持待核对，不自动重复播报或伪造已读。
- receipt 仅证明交给通话，不证明用户听懂、验收或动作执行。
