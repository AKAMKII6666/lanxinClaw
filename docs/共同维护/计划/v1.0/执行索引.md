## 当前不变量

- Phone/张老板只发送协议 request，不直接执行电脑副作用。
- Worker `completed` 不等于 affair `closed`。
- 所有 message 必须可按 `messageId`、`correlationId`、`affairId`、`jobId` 追踪。
- 新增协议字段必须同步 docs、schema、tests。
- 控制面板只消费 companion backend 暴露的数据契约，不直接发起电脑副作用。

## 风险

- 如果 v1.0 阶段过早接真实 OpenClaw，会导致协议和执行细节互相污染。
- 如果 schema 真源不明确，后续 companion 与 phone 会各自实现一套消息形状。
- 如果 mock companion 不模拟 blocked/permission 场景，后续“虚拟责任人”体验会缺关键状态。
- 如果控制面板字段在 v1.2 才临时补，会让 UI、protocol 和 companion backend 三边互相迁就。
