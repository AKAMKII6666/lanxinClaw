# v1.0 计划说明

## 版本目标

v1.0 的目标是跑通“协议到本地 mock companion”的可验证闭环。

本版本不追求真实控制电脑，也不接真实 OpenClaw。它要先回答清楚一件事：电话端、张老板、companion 和 worker 之间到底如何传 message、如何建 affair、如何委派 job、如何汇报 blocked/completed。

控制面板设计稿在本版本不落真实界面，但要提前转成可实现的数据契约。总览、任务、权限、诊断和张老板页需要的状态，都必须先在协议、schema、examples 和 mock companion 中找到对应数据来源。

## 对应阶段

| 阶段 | 目标 | 产出 | 完成标准 |
|------|------|------|----------|
| P0 协议收敛 | 把草案变成可实现协议 | message type 清单、状态机、schema、examples | 每个核心 message 都有方向、payload、错误、权限要求 |
| P1 Mock Companion | 不接 OpenClaw，先模拟电脑端 | 本地 WebSocket/HTTP 服务，能配对、收 job、回 progress/blocked/completed | 脚本能创建 affair/job，并收到状态 |
| P2 Protocol SDK | 把协议变成可复用代码包 | `packages/protocol`：types、validators、message helpers | examples 能通过 validator，错误消息稳定 |

## 范围

- 补全协议 message catalog。
- 补齐 pairing、session、affair、job、chat、permission 的 schema。
- 根据控制面板设计稿定义 UI 状态快照、任务摘要、待确认请求和诊断报告的数据形状。
- 为总览、任务、权限、诊断、张老板入口补充 examples。
- 建立 TypeScript monorepo 骨架。
- 实现 `packages/protocol`。
- 实现 `apps/mock-companion`。
- 写 contract tests。
- 将 protocol tests 接入 `npm run quality`。

## 非目标

- 不做真实 mDNS discovery。
- 不做真实 desktop companion UI。
- 不实现 Electron、React 或 MUI 代码。
- 不接真实 OpenClaw runtime。
- 不改 `openclaw/openclaw`。
- 不接澜星电话主仓。
- 不做真实自动回电。

## 控制面板数据契约

v1.0 只定义控制面板的数据面，不定义视觉实现。

| 页面 | v1.0 必须定义的数据 | 用途 |
|------|---------------------|------|
| 总览 | companion status snapshot、Claw core status、credential status、device connection status、张老板 status、current affair summary | 让 UI 一屏判断系统是否可用 |
| 任务 | affair summary、job summary、progress event、blocked detail、acceptance criteria | 让 UI 展示事务和 job 的当前状态 |
| 张老板 | chat message、context attach request、active affair reference | 让电脑端后续可以补充路径、日志、URL |
| 权限 | permission request、permission decision、permission scope、risk level | 让待确认卡片有稳定字段 |
| 诊断 | diagnostic report、service probe、environment probe、last error summary | 让诊断页不依赖临时日志拼接 |

这些数据必须由 companion backend 或 protocol mock 提供。UI renderer 后续只能消费这些契约，不直接读取 API key、执行命令或绕过 permission gate。

## v1.0 闭环

```text
模拟电话/张老板
  -> affair.create
  -> job.create
  -> mock companion
  -> status.snapshot / permission.request
  -> job.progress
  -> job.blocked / job.completed
  -> affair.waiting_acceptance
```

## 验收标准

- `npm run quality` 通过。
- 协议 docs、schema、examples 一致。
- `packages/protocol` 可以校验合法与非法 message。
- `apps/mock-companion` 可以模拟 progress、blocked、completed。
- `apps/mock-companion` 可以返回控制面板所需的 status snapshot、permission queue 和 diagnostic report。
- 至少有一个端到端脚本跑通 v1.0 闭环。
