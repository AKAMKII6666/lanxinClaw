# 0002 安装默认授权档

- 日期：2026-09-06
- 状态：已采纳（2026-09-07 修订）

## 背景

联调表现为「电话/配对看起来通，电脑侧永远干不了活」：OpenClaw browser 默认关闭，诊断黄灯诱导用户去勾开关；另曾短暂试验过 `job.create` 静默授权，与「任务发放仍要点授权」的 UX 意图冲突。

## 决议

澜星 Claw 消费安装档采用分层边界：

1. **OpenClaw 侧**：自托管默认开启 browser（**有头窗口** `headless=false`，用户可见操作过程）；产品不走 `web_search` 主路径。磁盘/命令/联网/Git/截图等执行工具面保持默认可用。
2. **Companion 权限 UX**：任务发放仍走 `needs_permission` + 用户确认后再委派；**不对** `job.create` 做静默 `allow_for_job`。配对确认照旧。
3. 界面不暴露硬核工具开关与 `web_search` 技术状态；权限页后续可再细调，本决议不强制改版。
4. 仍拒绝：`secrets.read`、工作区越界；仅模型等凭据需用户填写。

## 修订说明（2026-09-07）

- 撤回「基线权限同 tick 静默授权、不依赖用户点授权」条款。
- browser 默认由 headless 改为有头显示，便于用户观察执行现场。

## 后果

- 实现落在 companion permission policy、protocol job.create、gateway openclaw.json、onboarding/诊断 UI。
- Agent 不得在无新决议的情况下把 browser 改回默认关闭，或再次对基线权限做静默 `job.create` decide。
