# 澜星 Claw 控制面板设计向导

## 文档目的

本文用于指导澜星 Claw Windows 电脑端控制面板的第一版界面设计。它不是最终视觉稿，而是给 Pencil、Cursor 或后续前端实现使用的产品与布局向导。

控制面板的核心作用是让用户看清楚：电脑端 Claw 是否可用、电话是否已连接、张老板是否在线、当前有什么事务正在被盯、系统有没有卡住、哪些权限已经授予。

## 为什么需要控制面板

澜星 Claw 不是普通聊天应用，它会把澜星电话、张老板、OpenClaw 执行能力和用户电脑连接起来。只要涉及“让张老板通过 Claw 管电脑上的事”，用户就必须能随时看见系统状态和安全边界。

没有控制面板会带来几个问题：

- 用户不知道 OpenClaw core 是否启动。
- 用户不知道 API key 是否已同步、是否过期。
- 用户不知道澜星电话是否已经连上电脑。
- 用户不知道张老板是否在线、是否正在盯事务。
- 用户不知道 Claw 正在执行什么、是否 blocked、是否需要确认。
- 用户不知道自己给过哪些权限，也不知道如何撤销。

所以控制面板不是装饰性 UI，而是“信任界面”和“事务工作台”。

## 产品定位

控制面板是 Windows 端 Lanxing Claw Companion 的主界面。

它承担以下职责：

- 展示运行状态。
- 展示连接状态。
- 展示张老板状态。
- 展示事务和 job 状态。
- 接收用户授权确认。
- 接收用户粘贴的精确文字上下文。
- 展示安全审计和诊断信息。

它不承担以下职责：

- 不做人格化聊天模型本体。
- 不替代 OpenClaw 执行界面。
- 不绕过 companion 后端的权限判断。
- 不直接存储明文 API key。
- 不把 worker completed 自动当成 affair closed。

## 信息架构

第一版建议使用五个主导航页：

| 页面 | 目的 | 关键问题 |
|------|------|----------|
| 总览 | 一眼看懂系统是否可用 | 现在能不能让张老板管电脑？ |
| 任务 | 查看张老板交给 Claw 的事务与 job | 哪些事在跑，哪些事卡住了？ |
| 张老板 | 电脑端文字聊天与上下文补充 | 路径、日志、URL 怎么准确告诉张老板？ |
| 权限 | 管理配对、授权和待确认动作 | 电话端能做什么，哪些操作要我确认？ |
| 诊断 | 查看环境、服务、网络和日志 | 为什么连不上或跑不起来？ |

## 总览页需求

总览页是打开应用后的第一屏，必须用很少的文字回答五个问题：

1. Claw core service 是否已启动。
2. API key 是否已同步。
3. 澜星电话是否已连接。
4. 张老板是否在线。
5. 当前是否有任务正在运行、blocked 或等待确认。

### 状态卡片

总览页顶部放 5 个紧凑状态卡：

| 卡片 | 状态枚举 | 主操作 |
|------|----------|--------|
| Claw 核心服务 | 未安装 / 未启动 / 启动中 / 已运行 / 异常 | 启动 / 重启 / 查看诊断 |
| API Key | 未配置 / 已同步 / 已过期 / 需重新授权 | 同步 / 重新授权 |
| 澜星电话 | 未发现 / 已发现 / pairing 中 / 已连接 / 断开 | 连接 / 重新配对 |
| 张老板 | 离线 / 在线 / 通话中 / 正在盯事务 / 等待用户 | 打开聊天 |
| 当前任务 | 无任务 / 运行中 / blocked / 待确认 / 待验收 | 查看任务 |

## 任务页需求

任务页展示张老板给澜星 Claw 的 affair 和 job。它要像事务工作台，不像普通日志列表。

### 任务列表字段

| 字段 | 说明 |
|------|------|
| 事务标题 | 用户委托给张老板的事情 |
| 状态 | clarifying / ready / running / blocked / paused / waiting_acceptance / closed |
| 当前 job | 当前委派给 OpenClaw 的 job |
| 最近进展 | 给用户看的自然语言摘要 |
| 阻塞原因 | blocked 时展示 |
| 恢复条件 | resume condition |
| 更新时间 | 最近状态变化时间 |

### 任务详情字段

- 事务目标。
- 用户原始描述。
- 已确认上下文。
- acceptance criteria。
- 当前状态。
- 已尝试步骤。
- 当前 blocker。
- resume condition。
- 权限记录。
- OpenClaw 执行摘要。
- 操作按钮：暂停、恢复、取消、请求用户验收、关闭。

## 张老板页需求

张老板页是电脑端文字入口，解决电话语音不适合表达精确文本的问题。

### 核心能力

- 用户可以粘贴文件路径、错误日志、URL、命令输出。
- 用户可以选择附加到当前通话或指定 affair。
- 张老板可以在这里回报事务状态。
- **通话中主路径**：phone 收到桌面 `chat.message` / `chat.context_attach` 后主动注入当前 realtime 会话，并口头确认原文、询问意图（用户不必再让张老板去拉 FC）。
- **离线 fallback**：不在通话或注入失败时，通过 FC `companion.fetch_pending_context` 让张老板读取 pending 上下文。

### 聊天页线稿

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 张老板                                                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│ 当前上下文：修好 xxx 项目代码问题                                           │
│ ┌─────────────────────────────────────────────────────────────────────────┐ │
│ │ 张老板：我现在在看这个项目，刚才测试卡在一个路径问题上。                  │ │
│ │ 用户：F:/workspace/xxx/src/main.ts 就是这个文件。                         │ │
│ │ 张老板：收到，我把这个路径补进当前事务里，让 Claw 重点看这里。             │ │
│ └─────────────────────────────────────────────────────────────────────────┘ │
│ ┌─────────────────────────────────────────────────────────────────────────┐ │
│ │ 粘贴路径、日志、URL 或说明...                                             │ │
│ └─────────────────────────────────────────────────────────────────────────┘ │
│ [发送给张老板] [附加到当前通话] [附加到指定事务]                            │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 权限页需求

> 产品档（见 [0002-安装默认授权档](../../决议/0002-安装默认授权档.md)）：OpenClaw 侧浏览器等工具默认开启（有头可见）；Companion **任务发放仍须用户确认授权**。权限页继续承担配对管理与待确认队列；`secrets.read` 等敏感项默认拒绝。

权限页帮助用户理解：电话是否已配对、能否撤销，以及当前待确认的权限请求。

### 权限模块

- 已配对设备列表。
- 当前连接设备。
- 可撤销 pairing。
- OpenClaw 默认可执行能力说明（与「是否弹授权」分层）。
- 待确认队列（任务发放与敏感权限）。
- Audit log 入口。

### 待确认卡片

每张待确认卡片必须说明：

- 谁请求的：张老板 / companion / OpenClaw adapter。
- 为什么请求。
- 作用范围。
- 风险等级。
- 允许时长：一次 / 当前 job / 永久规则。
- 拒绝后会发生什么。

## 诊断页需求

诊断页用于排查“为什么没连上、为什么跑不起来、为什么 Claw 没反应”，并提供「运行偏好」：托管浏览器走本地代理（默认开；改开关/地址后点「应用并重启」才写入并热重启 Gateway；开启时会配套放宽托管浏览器 SSRF 以便代理可用）。

### 诊断项

| 项目 | 状态 |
|------|------|
| Companion service | 已运行 / 已停止 / 异常 |
| OpenClaw core | 已运行 / 缺失 / 版本不兼容 / 异常 |
| Node | 已检测 / 缺失 / 版本不支持 |
| pnpm/npm | 已检测 / 缺失 |
| Git | 已检测 / 缺失 |
| LAN discovery | 正常 / 被阻塞 / 不可用 |
| Firewall | 已放行 / 被阻止 / 未知 |
| API key | 已配置 / 缺失 / 已过期 |
| Secure storage | 可用 / 不可用 |
| Last job error | 无 / 错误摘要 |

## 布局规范

## 整体布局

- 使用左侧固定导航 + 右侧内容区。
- 左侧导航宽度建议 160px 到 200px。
- 内容区最大宽度不强行居中，Windows 桌面应用应优先利用横向空间。
- 首页状态卡使用紧凑网格，避免做成营销页 hero。
- 任务列表和详情使用左右分栏，方便扫描和切换。
- 弹窗只用于 pairing、权限确认、高风险操作，不用于展示普通状态。

## 密度

- 这是工具型控制台，不是官网首页。
- 信息密度应高于普通 landing page。
- 卡片圆角不超过 8px。
- 状态卡高度保持稳定，不因文字变多而跳动。
- 长路径要允许复制，显示时中间省略，例如 `F:/workspace/.../main.ts`。

## 组件建议

优先使用 MUI 组件：

- `AppBar` 或自定义顶部栏。
- `Drawer` 或固定侧边栏。
- `Card` 用于状态卡和任务项。
- `Tabs` 可用于任务详情内部分区。
- `Dialog` 用于 pairing 与高风险确认。
- `Alert` 用于 blocked、error、waiting_acceptance。
- `DataGrid` 可用于 audit log。
- `Chip` 用于状态标签。
- `ButtonGroup` 用于 allow_once / allow_for_job / deny。

## 颜色规范

整体风格应偏安静、可信、工作台感。避免大面积紫蓝渐变、营销式大 hero、装饰性光斑。

### 建议色板

| 用途 | 色值 | 说明 |
|------|------|------|
| 背景 | `#F6F7F9` | 主窗口背景 |
| 面板 | `#FFFFFF` | 卡片和内容面板 |
| 边框 | `#D8DEE8` | 分割线和卡片边框 |
| 主文本 | `#18202A` | 标题和正文 |
| 次文本 | `#5C6675` | 辅助信息 |
| 品牌主色 | `#2563EB` | 主要操作按钮 |
| 成功 | `#15803D` | connected、running、completed |
| 警告 | `#B45309` | waiting、needs_permission |
| 危险 | `#B91C1C` | error、blocked、revoke |
| 信息 | `#0369A1` | discovery、syncing |

### 状态颜色

| 状态 | 颜色 |
|------|------|
| 已连接 / 已运行 | 成功 |
| 启动中 / pairing 中 | 信息 |
| 待确认 / 待验收 | 警告 |
| blocked / 异常 | 危险 |
| 未配置 / 未发现 | 次文本 |

## 文案规范

- 用户可见文案使用中文。
- 技术标识可以保留英文，例如 `job.blocked`、`workspace.write`、`OpenClaw adapter`。
- 错误文案不要只写 error code，必须解释用户能做什么。
- 张老板相关文案要像负责的人，但不要假装底层执行一定正确。

示例：

```text
我这边让 Claw 试了几次，npm registry 还是访问不了。
这个不像代码问题，更像网络被拦住了。
我先把这个事务停在这里；你恢复网络后，我可以从安装依赖那一步继续。
```

## 技术方案

## 技术栈建议

第一版 Windows companion UI 建议使用：

```text
Electron
  + React
  + MUI
  + TypeScript
  + companion backend
```

理由：

- Electron 适合 Windows 桌面壳、托盘、开机启动、本地端口和系统权限交互。
- React + MUI 能快速做稳定的工具型控制台。
- TypeScript 方便复用 `packages/protocol` 的 types 和 validators。
- Companion backend 可以与 UI 分离，保持权限判断不被前端绕过。

## 进程结构

```text
Electron main process
  -> 管理窗口、托盘、开机启动、本地服务生命周期

Companion backend
  -> pairing、session、permission gate、job store、audit log、OpenClaw adapter

React renderer
  -> 展示状态、任务、聊天、权限、诊断
  -> 不直接执行文件/命令/git/network 副作用

OpenClaw adapter
  -> 接受 companion 授权后的 job
  -> 回传 progress、blocked、completed、failed
```

## 数据来源

| UI 区块 | 数据来源 |
|---------|----------|
| Claw 核心服务 | companion backend service status |
| API Key | credential manager status，不返回明文 |
| 澜星电话连接 | pairing/session store |
| 张老板状态 | phone session + affair supervisor status |
| 任务列表 | affair/job store |
| 待确认 | permission request queue |
| 审计日志 | audit log store |
| 诊断 | environment probe |

## 安全要求

- Renderer 不直接访问 API key。
- Renderer 不直接执行命令。
- Renderer 不直接修改 permission store。
- 所有高风险动作必须经 companion backend 生成 permission request。
- Audit log 不记录 API key、token、私钥或完整 secret。
- 待确认弹窗必须展示 scope、reason、risk、duration。
