# 产品简述

## 产品定义

澜星 Claw 让张老板成为电脑侧工作的“虚拟责任人”。

张老板负责一个 affair 的完整生命周期：

- 理解用户想要做什么。
- 追问缺失上下文。
- 确认 acceptance criteria。
- 把具体执行委派给 OpenClaw 这样的 worker。
- 跟踪进度。
- 遇到 blocked 时先尝试合理恢复。
- 需要人类介入时暂停并联系用户。
- 关闭 affair 前请求用户验收。

张老板不负责亲自执行每一个技术操作。OpenClaw 或其它 worker 负责执行 task。张老板负责知道这件事推进到哪里、卡在哪里、是否已经到达用户可接受的结束状态。

## 用户体验目标

- 用户可以通过电话自然说话。
- 文件路径、URL、错误日志、命令等精确信息可以从电脑端 chat channel 补充。
- 电脑端 companion 可以在局域网被发现，并在明确同意后 pairing。
- 用户可以挂电话，张老板继续监督 affair。
- 当事务 blocked、done 或等待确认时，张老板可以回电或在电脑端提示。

## MVP

1. Desktop companion 在 LAN 上宣告自己。
2. 电话端发现 companion，并询问用户是否 pairing。
3. 首次 pairing 需要电话侧与电脑侧双确认。
4. 张老板创建包含 title、context、acceptance criteria、status 的 affair。
5. Companion 接收 affair job，并委派给 OpenClaw adapter。
6. Adapter 汇报 progress、blocked、completed 或 failed。
7. Worker 完成后，张老板把 affair 标为 waiting_acceptance，而不是直接 closed。

## 非目标

- 替换 OpenClaw core agent engine。
- 把张老板人格逻辑塞进 OpenClaw core。
- 让电话端直接执行任意电脑命令。
- 在没有明确 pairing 与 permission 的情况下静默传输 API key。
- 把 worker 的 `done` 视为用户验收。
